# CCF-A/B 年度论文精读运行约定

## 授权与时间口径

目标北京时间（Asia/Shanghai）每天10:00执行，长期归档到 `CCF_Papers/YYYY-MM-DD/`。日程由调度端维护；本次首期制作不新增或更改自动化，也不把计划时间当成已启用的证明。

此方向覆盖 AI/LLM 训练、推理、对齐、采样及相关基础研究，不局限于 OPSD。按运行当年的会议/期刊录用年度选择，允许预印本更早公开。根目录针对 VLM/OPSD 的最近一个月规则不适用于这里。以运行日已公开的正式证据为限，不能用尚未证实的未来录用填数。

用户已授权写入现有 `daihuangyu/papers-daily` 的 main；本次亦明确允许现有本地 checkout 与 SSH 普通推送，覆盖根运行约定中针对此次操作的云端专用限制。不创建新仓库、不强制推送、不改其他方向历史内容。以后每次仍以当次可用且已授权的连接/工作环境为准，不复制凭据。

## 筛选与身份核验

1. 每次读取当前 CCF 官网目录，记录正式版本、修订日、分类页码与来源；不用过时分类或未生效草案。
2. 每期目标5篇，偏好4篇A加1篇B、3篇oral加2篇poster。证据与质量优先；spotlight独立记录，不冒充oral；不足或无法达到配比必须如实说明。
3. 只纳入主会 full/regular 长文或正式期刊常规论文；排除 workshop、Findings、短文、demo、摘要、technical brief。展示形式为 poster 不等于论文类型为 short。
4. 录用与展示必须有官方 program、论文页面、公开 decision 或 proceedings 证据。只读了会议页面就不声称读过 OpenReview decision/review。主会、期刊、预印本和展示安排分别记录。
5. 查引次数用 OpenAlex、Semantic Scholar 等可核验论文记录，保留数值、原始记录/来源、查询日和匹配方式。查不到填 null 与原因，不以浏览、点赞、stars 替代。优先同主题、相近发表时长的高影响工作，避免仅按裸引用数奖励更早公开的论文；非穷尽搜索不宣称全局最高引用。
6. 先读 sources.json 和全部方向所有 manifest；按去版本 arXiv、DOI、规范URL、规范标题与改题别名全仓去重。正式版与预印本算同篇；人工核对作者、项目页与改题链。论文升级版本不自动算新论文。

## 精读要求

逐篇读完整正文与附录，记录实际PDF版本、页数、哈希。中文解释动机、基础概念、问题定义、机制、所有核心公式的符号与关键推导；给可手算例子、训练/推理伪代码、loss/reward、数据构建/过滤/采样、模型规模、关键超参数。报告训练步数、硬件、用时、显存、GPU-hours/TPU-hours与费用；未披露就明说，推导估算与作者实测分开。

对主要结果、baseline、消融、初始化、数据、算力和评估条件作同设置比较。保留退化单元、指标定义、测试集选参、全局/局部预算、理论/实现差距、版本矛盾与复现限制。没有运行模型时不得声称已复现实验。

优先原始架构/流程图及关键实验图表，直接从原PDF裁取，存assets。逐图给原图号、物理PDF页码、来源、条件与阅读说明；不重画或生成实验数据。图源清单保存裁切坐标与哈希。提供官方论文、项目/代码、作者博客（若存在）及按难度分级的基础材料，不把辅助材料算入五篇。

## 制品与检查

当日目录必须有完整 `report.md`、由同一Markdown生成的全文 `report.pdf`、`manifest.json`、`assets/`。不得用短版PDF替代完整精读。manifest记录年度口径、等级、录用/展示证据、引用查询、实际数量、检索与剔除日志、原图与PDF检查。不足五篇可以发布真实数量及原因，不补旧文/博客凑数。

PDF嵌入中文/数学字体，缺字即失败。逐行核对Markdown可见内容与PDF文本，核对全部图片；逐页渲染并检查标题、表格、公式、代码、图片/图注、页码，无裁切、叠字、空白或缺页。发布用的文件必须是最后一次通过检查的版本。复现脚本可以放仓库scripts，执行环境和QA结果写入assets/QA.md。

运行 `python3 -m unittest discover -s scripts/tests -v` 与 `python3 scripts/update_index.py`；重建根README、方向README、sources.json。CCF校验按当年录用，不误套最近一月；spotlight/unknown独立；有引用数必须有出处和日期。新增标题别名必须参与查重。

## 发布与幂等

发布前fetch并记录main基点、其他方向tree及本次路径清单；若并发更新，先保留并整合新提交，再运行必要校验。只提交本方向新文件、必要索引/校验脚本，不触碰无关修改。普通commit/push，禁止force。

推送成功后再fetch/读取远端：核对main提交和每个本次新增/修改文件的blob，核对VLM/OPSD等其他方向与基点一致（若期间有合法并发变更，则验证其提交仍为祖先且未被本次回退）。返回Markdown、PDF、commit链接及真实不足/阻塞。

若当日已有完整且通过检查的报告，优先验证后返回，避免再次选题或覆盖。若之前失败，恢复未完成步骤；失败阶段准确报告，不把写了Markdown、仅本地有PDF或仅发出push请求当成已发布。
